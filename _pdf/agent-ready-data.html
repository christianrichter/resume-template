1. A semantic layer

Every table, column and metric gets one clear name and one description, maintained with the data models (for example in dbt). The same definitions serve your analysts and dashboards.

2. Tested query patterns

The questions that are easy to get wrong (point-in-time logic, deduplication, the right join between two business dates) get a tested SQL pattern the agent loads when needed.

3. A secure access layer

An MCP server between agent and data: read-only SQL, every query validated before it runs, limits on cost and rate, authentication and query logging.

4. An accuracy test set

Real questions from your team with expected answers, run on every change. You know how good the agent is today, and notice when something breaks.

Built and running in production

Shibui Finance, my own product: a public MCP server that makes 60+ years of US stock market data queryable in plain English from Claude, listed in the official MCP Registry. It runs on exactly this approach: a semantic layer on dbt, PostgreSQL and DuckDB, tested SQL patterns, read-only SQL with validation before every query, and rate limiting with an open-source module I wrote.
